# ADR-0006: Query the database with Kysely and SQLAlchemy, with types generated from the schema

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-29 |
| **Chapter** | The app; 02 (query tuning) |

## Context

The API and the worker query the same database, whose schema belongs to the SQL migrations ([ADR-0005](0005-plain-sql-migrations-with-dbmate.md)). Each service's types must match the real schema, and chapter 02 tunes queries, so the SQL must stay visible.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| **API: Kysely + kysely-codegen** | Typed SQL query builder; types generated from the migrated database; doesn't own the schema | `CHECK (... IN (...))` columns come out as plain `string` |
| API: Drizzle with `drizzle-kit pull` | Typed and popular | Its migration commands overlap dbmate and must be left unused |
| API: Prisma | Typed and popular | Its own schema file and migration engine |
| **Worker: SQLAlchemy 2.0 on psycopg 3 + sqlacodegen** | Typed models generated from the database; mature | Heavier than plain SQL for a few queries |
| Worker: plain psycopg 3 with `class_row` | Simplest | Row classes written by hand |

## Decision

- **API:** Kysely, with types generated by kysely-codegen.
- **Worker:** SQLAlchemy 2.0 on psycopg 3, with models generated by sqlacodegen.
- **Generated types are never edited by hand.** One script runs the migrations and regenerates every generated file:
  - the database types for both services;
  - the job payload types ([ADR-0004](0004-bullmq-jobs-with-a-database-sweep.md));
  - the site's API client, from the API's OpenAPI description.
- **Statuses are Postgres `ENUM`s**, so the generated types stay narrow.

## Consequences

**Positive:**
- A schema change shows up as a type error in both services.
- The SQL stays visible for chapter 02.

**Negative / accepted trade-offs:**
- Removing an `ENUM` value is painful; booking statuses only ever grow.
- Two generators to keep pinned.
- A CI check that the generated files are up to date only comes with chapter 07.
- psycopg 3's prepared statements will clash with PgBouncer in transaction mode. That's left for chapter 02 to find.

**Revisit if:**
- kysely-codegen or sqlacodegen fall behind the libraries they generate for.
